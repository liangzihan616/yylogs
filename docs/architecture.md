# 架构与模块划分

本文件只描述**分层职责与数据流**，不含实现代码。

## 1. 分层

```text
┌─────────────┐   只读事件    ┌──────────────┐   结构化记录   ┌────────────┐
│  capture    │ ───────────▶ │   analysis    │ ───────────▶ │     ui     │
│  采集层      │              │  解析/统计层   │              │   界面层    │
└─────────────┘              └──────────────┘              └────────────┘
        │                            │                            │
        └──── 原始事件落盘 ──────────┴──── 汇总/曲线/报表 ────────┘
                    （本机，%LOCALAPPDATA%/YYLOGS）
```

- **capture**：在用户明确开始时建立只读观测，按白名单收集战斗事件与状态采样，写入本场记录目录；用户停止时收尾并校验完整性。不会自动启动、不修改游戏状态。
- **analysis**：把原始事件整理成时间轴、伤害/治疗分段、Buff 覆盖区间、Boss 血量与真气曲线、结算核对与 RD 估算。所有统计都标注口径与不确定性。
- **ui**：四个观测视角（总览、自身 Buff、Boss 状态、队员状态）+ 记录管理。只消费 analysis 的输出，不直接读游戏。

## 2. 关键数据对象

| 对象 | 说明 |
| --- | --- |
| 战斗记录 | 一场战斗的完整观测集合，包含事件流、状态采样、元信息和校验值 |
| 事件 | 带时间戳的单条战斗事实（伤害、治疗、Buff 施加/移除等），保留原始 ID，不做语义回填 |
| 时间轴轨道 | 某一效果在时间上的覆盖区间序列，区分观测通道（原生事件 / 采样） |
| 曲线 | Boss 血量、真气等连续量的归一化序列，缺口显式标记 |
| 估算结果 | RD 等派生指标，附带覆盖率、适用区间与“未纳入”清单 |

## 3. 统计口径原则

1. **不猜**：无法确认来源、无法确认覆盖的区间不分配、不补齐。
2. **不重复**：同一事件的多通道副本去重，同族区间取并集。
3. **可核对**：所有派生指标保留原始 ID 与证据链，界面上能看出“这个数字是怎么来的”。
4. **不越权**：只读观测、字段白名单、容量上限、可随时停止。

## 4. 界面信息架构

- **总览**：本场结论（总伤、DPS、成员排行、提供 RD、伤害贡献）
- **自身 Buff 观测**：自己的增益/减益覆盖与来源
- **Boss 状态观测**：血量/真气曲线 + Debuff 覆盖率（可展开）
- **队员状态观测**：单队员 DPS/HPS 曲线，可叠加 Boss 血量与真气，悬停查看技能明细

## 5. 约束

- 采集只在用户显式操作后开始，默认不启用；
- 不写游戏内存、不调用游戏函数、不做任何保护绕过；
- 所有数据留在本机，导出行为由用户主动触发。
