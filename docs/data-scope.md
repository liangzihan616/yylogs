# 数据口径与不确定性说明

程序里的每个数字都对应一个明确口径，界面会保留证据与限制说明。

## 观测区间

- 统计区间来自本场战斗的观测窗口；区间外事件不计。
- 曲线为采样序列，采样间隔内的变化不可还原；缺口显示为空，不补点、不插值。
- 超长战斗存在容量上限，达到上限会记录截断原因并在界面提示。

## 伤害与治疗

- 伤害为**逐次观测事件**的累计，不是服务器结算总额；与游戏内面板的差异会显式保留。
- 治疗同理，单独统计，不混入伤害。
- 结算类伤害（游戏结算面板给出的累计）单独归类，按快照序号记录，避免与逐次事件重复计入。

## Buff 覆盖

- 覆盖区间来自原生事件通道；仅当缺少原生通道时才回退到采样轨道，并在界面标注。
- 同族多个实例取并集，重叠且无法确定归属的部分不分配。

## RD（提供增益）估算

- 只统计“增伤 Buff **有效覆盖区间内**队友**实际发生**的技能伤害”，再乘用户给定的有效估算系数；
- 不使用全场总伤害套固定公式，不使用平均覆盖率回填区间外的伤害；
- 自己给自己的增益不转移；无法证明接收者的部分不转移；
- 输出附带覆盖率、适用区间和“未纳入”清单，属于估算而非服务器 RD。

## 归类原则

- 伤害事件保留原始技能 ID 与计算点 ID，显示名只做展示归类；
- 由 Boss 身上减益结算、但事件仍带触发技能 ID 的伤害，按**计算点**归类，避免把不同机制混在一起；
- 未知或冲突来源保持“未识别”，不强行归到某个技能。

## 隐私

- 记录只保存在本机 `%LOCALAPPDATA%/YYLOGS`；
- 导出日志包由用户手动触发，内容为本次观测数据；
- 程序不上传数据、不联网上报。
